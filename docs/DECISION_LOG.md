## 2026-05-31 - 使用 Godot 4.6.x 和 GDScript

- 决策：Demo 使用 Godot 4.6.x stable 和 GDScript。
- 背景：团队要在 2026-08-15 前交付 Windows 可执行 Demo 和演示视频。
- 原因：Godot 2D 工作流轻量，GDScript 上手快，适合小团队快速迭代。
- 影响范围：程序架构、导出流程、项目目录和协作规范。
- 复盘条件：如果性能、导出或团队学习成本严重影响 Demo 交付，再复盘技术路线。

## 2026-05-31 - Demo 优先做美术演示型垂直切片

- 决策：优先打磨手工关卡、角色动作、命中特效和录屏表现，不先做完整随机肉鸽。
- 背景：项目目标是先提交高质量 Demo。
- 原因：有限时间内，稳定可录的垂直切片比完整系统更能展示品质。
- 影响范围：关卡结构、素材优先级、系统范围、里程碑安排。
- 复盘条件：当战斗和素材完成度稳定后，再评估随机房间和更多构筑系统。

## 2026-05-31 - 采用 GitHub 分支协作流程

- 决策：`main` 作为稳定演示基线，`develop` 作为日常集成，功能和素材从分支开发。
- 背景：团队四人协作，需要减少冲突和误提交。
- 原因：分支模型清晰，适合程序、美术、策划并行推进。
- 影响范围：提交、PR、Review、版本留档。
- 复盘条件：如果 PR 流程过重或分支长期不合并，每周例会复盘调整。

## 2026-05-31 - AI 素材可以直接作为 final

- 决策：AI 生成图、动作帧和 spritesheet 可以直接作为 `final` 素材接入。
- 背景：团队希望更快推进 Demo 画面完成度，并已明确后续如需重绘会单独提出。
- 原因：当前阶段优先做可运行、可录屏的高质量垂直切片，AI final 能缩短素材交付周期。
- 影响范围：像素图、VFX、道具图标、UI、角色、敌人、Boss、场景 tiles/props 和素材清单。
- 复盘条件：如果后续发现风格、版权、可读性或质量风险，再单独决策收紧规则或替换具体素材。

## 2026-05-31 - 允许 AI 游戏图标作为 Demo 应用图标接入

- 决策：本轮 `icon_neon_machine_demo_v1` AI 图标可标记为 `final`，并接入 Godot 项目图标与 Windows 导出图标。
- 背景：当前任务明确要求按已确认规格生成 1024x1024 正式游戏图标，核心表达为机械危机、冷峻压迫与低头觉醒。
- 原因：图标在 1024、128 和 64 尺寸下都保持了半脸阴影、单眼发光、冷蓝红光和机械城市压迫感的可读性。
- 影响范围：项目应用图标、Windows 导出图标、`assets/ui/`、素材清单和 AI 素材政策例外。
- 复盘条件：如果后续确定人工重绘版本、主视觉方向调整，或商店上架规范要求不同图标层级，则替换本图标。

## 2026-05-31 - 首个玩法切片只做初始匕首

- 决策：当前玩法分支只精修初始匕首，增加三段普攻和一个 Demo 能量突进斩，不实现多武器槽或快速切换。
- 背景：团队已经有世界观、武器策划和初步美术参考，需要尽快形成可录屏的 30-60 秒战斗路线。
- 原因：先把一把武器的移动、连段、命中停顿、能量反馈和敌人节奏打磨出来，比同时铺开多武器系统更稳。
- 影响范围：玩家控制器、HUD、攻击数据、武器数据、关卡目标推进和后续素材接入顺序。
- 复盘条件：当初始匕首手感、正式动画和命中特效稳定后，再评估是否抽象正式多武器框架。

## 2026-05-31 - 动态背景采用拆分 tiles/props

- 决策：实验室和城市高架背景采用拆分 tiles/props 与循环 spritesheet，不制作全屏背景帧序列。
- 背景：团队希望全路线背景更有动态氛围，并且后续由人工像素美术逐步替换正式素材。
- 原因：拆分 props 更容易复用、调光、替换和保护战斗可读性，也能让程序先搭好动态节点。
- 影响范围：关卡背景节点结构、背景素材交付路径、素材清单和美术排期。
- 复盘条件：如果拆分 props 导致性能或制作成本过高，再评估减少动画点数量或合并部分远景层。

## 2026-06-02 - 主角初始近战改为拳头开局

- 决策：将当前默认近战主线从匕首切换为拳头原型，优先生成更有力量感、身体驱动更强的空手连段帧。
- 背景：现有刀系条带可以跑通系统，但不完全符合当前想要的角色打击感方向。
- 原因：拳头动作更容易直接表现预备、命中和收招的重量，也更适合先打磨角色本体的力量感与流畅度。
- 影响范围：`WeaponData` 默认资源、攻击命名、主角动画标签、像素图提示词和后续 AI 出图任务。
- 复盘条件：如果拳头版在实际试玩里不如刀系更好读或更好录屏，再评估是否改回刀系开局，或将拳头作为无武器起始态、刀作为早期强化。

## 2026-05-31 - 实验室背景接入首批 AI final

- 决策：实验室背景 tiles/props 首批素材以 AI 生成图和 AI 生成帧作为 `final` 运行时素材接入。
- 背景：团队明确要求先把实验室背景从 placeholder 切换为实际接入素材。
- 原因：能快速验证动态背景管线，并给后续城市背景和更多动态 props 形成流程模板。
- 影响范围：实验室背景素材、`ASSET_MANIFEST.csv`、AI 素材政策和动态背景验收。
- 复盘条件：如果后续画面风格或可读性需要调整，再单独替换这批 AI final 背景素材。

## 2026-06-02 - 先用过渡拳头条带完成运行时切换

- 决策：在正式高质量拳头帧未全部重绘完成前，先基于旧早期克隆体战斗帧剥离刀光与刀系读感，生成一版过渡 `combat_* / punch_*` 条带，用于先行实装、清理旧帧并测试游戏。
- 背景：当前目标已经包含“生成新帧后删除旧帧、实装并部署测试”，如果继续只停留在规范与提示词层，项目运行时仍会被旧刀系战斗帧占住。
- 原因：先完成过渡拳头 runtime 切换，可以尽早验证战斗节奏、命中窗口、资源目录和部署脚本；后续再把这版过渡条带替换成更高质量正式拳头帧。
- 影响范围：`Player.tscn`、`PlayerAnimationController.gd`、玩家运行时 SpriteFrames 资源、旧 `atk_* / skill` 逐帧目录、拳头素材生产与部署脚本。
- 复盘条件：当正式拳头帧整套完成并通过 GUI 手感验收后，评估是否保留任何过渡条带或仅保留其生产记录。
